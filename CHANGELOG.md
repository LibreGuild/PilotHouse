# Changelog

What changed in each release, newest first. The full notes are on the [releases page](https://github.com/LibreGuild/PilotHouse/releases).

Each release also has **Merge notes** for organisations that build their own copy of PilotHouse ([docs/customizing.md](docs/customizing.md)): what to look at when merging it. These cover new `[features]` keys (new features arrive switched on), new or renamed keys in `brand/brand.toml`, changes to `crates/custom` or `Store::apply_track`, and moved files.

## 0.8.0

- **A welcome tour.** The first start after this update shows eight cards, a picture that plays and three short lines each, that say what PilotHouse has: the agents and their two forms (the chat, or the agent's own CLI, one conversation), the three places to work, the browser, your own Chrome and your phone beside the chat, tests and Utilities, GitHub pull requests reviewed with an agent, slides and small apps, pictures edited and videos compressed in Studio, and the small things. The pictures show the thing happening (the agent's pointer presses a button, a review is written and posted), and stand still for anyone who asked the system for less motion. *Next* to the last one's *Done*, which is the only way to end it (the keys go through the cards and stop at the last). It shows once. Later, an update that adds something shows a card or two for it (*What's new*), and an update that only fixes things shows none. *Help → Welcome tour* brings the cards back, and so does *Settings → About*.
- **Settings says which version this is.** Small, beside its title (*Settings* v0.8.0), so it is there without opening *About*.
- **Fixed: a workspace's own file could be changed without asking once the workspace had a deck.** A workspace's chats change the files of the decks made from it without asking. A file an agent named without its folder (`src/main.rs`) was looked for in the deck's folder, found to be "inside" it, and let through, though the agent writes it in the workspace. Such a name is now taken from the folder the agent runs in, and asks.
- **Slides: a slide keeps only addresses of kinds it knows.** What a deck's page reads (a slide's file, something pasted) had `javascript:` links taken out, a list of what is refused, which a tab inside the word, `data:` and an SVG animation got past. Now a link, a picture or a video is kept only when its address is of a kind on a list, read as a browser reads it; SVG animations are left out. A link typed in the editor gets `https://` when it has no scheme (it led into the deck's own files before). An element copied from a slide travels on the clipboard as a tree of its parts and is built again from them: markup from a clipboard is no longer read as HTML.
- **The search is in the middle of the title bar.** It was the search and the ⋯ button beside it together that were centred, so the search stood left of the window's middle. Now the search is centred, with ⋯ to its right.
- **Slides, made beside a chat.** The Artifacts page starts with a row of what can be made there: the *Slides* card opens a new deck in a window of its own: the chat on the left, the deck on the right. Say what the deck is about and the agent drafts it; say what to change, or click something on a slide and say "this". By hand: add text, pictures, videos, tables, charts and shapes, move and resize with guides, type in place, restyle from the bar over the selection or the panel beside it, add slides from ten layouts, pick one of six looks, write speaker notes, and undo any step, yours or the agent's. A chart keeps its numbers, in the deck and in PowerPoint.
- **Slides: comments, presenting, sharing, export.** Comment on an element or a slide, and send a comment to the agent, which makes the change and answers in the thread. Present full screen, or with notes (the slides in a second window, on another screen when there is one). Share a deck on your network like any artifact; people who open it follow along while you present. Export a PDF, one web page, a picture of a slide, or a PowerPoint file with real text boxes, shapes, tables and charts, in the deck's fonts or in fonts every computer has.
- **Slides from a workspace: ask for a deck where the code is.** In a workspace's chat, "make a presentation about how this works" has the agent make a deck, read the project and write the slides. The deck shows beside the chat as it is written; **Open in Slides** opens it in its own window with the same conversation on the left, so the agent that changes the deck still knows the code. A deck's title bar says which workspace it works from, and changes it (also for a deck made under Artifacts).
- **Slides: start from a PowerPoint file.** *Start from a PowerPoint file* in an empty deck, a `.pptx` dropped on a deck, or *Open as Slides* on one in Files turns its slides into slides of the deck: text as text, pictures, tables, charts with their numbers, notes, the file's colours and fonts.
- **The presentation editor in Studio is gone**: Slides takes its place. *New presentation* and *Open a presentation* left the ⋯ menu; decks are made and listed under Artifacts. Presentations made with the old editor (in `Documents/PilotHouse Presentations`) are not opened any more: a `.pptx` exported from one opens as Slides.
- **Fixed: Utilities → Text → Diff could end the app** when one of the two texts was empty.
- **The column of icons starts with Workspaces.** The order is now *Workspaces*, *Chats*, *Bridge*, *Reviews*, *Artifacts*: where the work is done, then what goes on across it, then what is around it. The Bridge and Reviews say what they are when pointed at.
- **Usage in the status bar is one item.** It says *Usage* while all is well, names the limit that is close or reached when one is, and opens every agent's limits (and which agents report none, and why) with a way to *All usage*. The bar used to show each agent's windows side by side, which in practice showed only Codex.
- **An Edit menu on macOS** (Cut, Copy, Paste, Select All), as every Mac app has.
- **Artifacts.** A page an agent made for you (a budget planner, a dashboard, a report, a small game) can be kept as a PilotHouse artifact: ask for one in any chat, or say "publish this as a PilotHouse artifact" about a page you built. It gets an address of its own on this computer, opens in the built-in browser beside the chat, where you point at things and ask for changes, and reloads by itself when the agent publishes again. **Artifacts** in the column of icons lists everything made, with a picture of each; a click opens one in your browser, and its menu renames it, goes back a version, shows its folder or deletes it. What you enter in an artifact is kept with it (`window.artifact.storage`), the same in every browser, and an agent can read it to answer questions. Artifacts live in `Documents/PilotHouse Artifacts`; nothing is uploaded, and the address answers only on this computer.
- **Artifacts: share one on your network, and use it together, live.** *Share on your network…* in an artifact's menu gives a link for the people on the same network: they open the page in their own browsers while PilotHouse runs on your computer. They can take part (a game, a poll, a board) or only look; the dialog shows how many have it open, and **Stop sharing** closes it. Pages get a live room (`artifact.room`: who is here, messages between them) and a storage everyone shares (`artifact.shared`), so an agent can build a multiplayer game with no server to write. What you entered in an artifact for yourself is never given to a guest. Sharing ends when you stop it or quit; it is not the internet.
- **Android: mirroring a phone works as scrcpy and Android Studio do.** A phone's screen now comes from scrcpy's server, bundled and run on the phone, in place of `screenrecord`. Touch is live: a drag is followed while the finger is down, a long press and a fling are what they are on the phone, and the wheel scrolls (gestures used to be sent only on release). Text in any script can be typed and pasted, ⌘C brings the phone's selection back, a turned screen is followed at once, and the picture no longer restarts every three minutes. The phone stays as fast as it is: on a Galaxy S20 FE, 0.2% of an app's frames were late while mirrored, the same as with nothing mirrored. A screen hidden by another tool keeps streaming for 20 seconds, so coming back finds it there.
- **Fixed: a phone could become very slow while mirrored.** When video could not start on a device, its screen was streamed as raw frames, which the phone reads back from its GPU one by one (measured: 97% of frames late). On a computer that can decode video this is never used now; a device that streams no video is shown in snapshots, a few a second, and the toolbar says so.
- **Logcat reads like Android Studio's.** Text is selected by dragging, double and triple clicks and Shift, and copied with ⌘C (⌘A for everything shown); a click no longer opens a card over the list. A right click copies the message, filters by the line's tag or app, or sends to chat. Colours are quiet (amber warnings, red errors, plain text otherwise), long messages wrap, and a stack frame's file opens at its line.
- **Logcat: `package:mine`, and more of Studio's filter.** In an Android project the log starts on the project's own apps. The filter also takes `level:warn`, `-word`, `is:crash` and `is:stacktrace`. An app's lines are found by its processes as they start and end, so those of an app that crashed and started again are all there.
- **Logcat no longer loses what happened while another tool was in front**: once opened it runs for as long as its device is in use. It also shows under the mirrored screen, as a drawer of the Devices pane.
- **Devices are remembered.** A device connected over the network is saved, and connects again in one click, from the device menu or the *Connect a device* dialog; saved devices can be named and forgotten. The device chosen last is chosen again after a restart.
- **Connect a device: one page, and it says what went wrong.** Saved devices, phones adb finds on the network, phones on USB (*Switch to Wi-Fi*), an address, and pairing with a code are on one page. It stays open until a device is connected: a failure is explained in it, and nothing typed is lost.
- **The device menu** names each device with its Android version and, over the network, its address; creating, wiping and deleting emulators moved under *Emulators*.
- **Run an Android app: the card remembers and helps.** The module and variant chosen are kept per project, and a variant the build files do not show can be typed (*Other…*). A run starts the device's log and shows the app's lines; a crash is said on the card and in a notice that offers the stack to the chat. A failed build has *Send to chat*; an install refused because another build of the app is on the device offers *Uninstall and run again*; a device older than the app's `minSdk` is said before building. A menu on the card stops the app, clears its data, grants its permissions, opens a link in it or uninstalls it. The plain `installDebug` and `assembleDebug` entries are not listed beside the card any more.
- **Workspaces are one list, opened from the title bar.** The name of the workspace in front is a button: it opens the list of workspaces, the one used last on top, each with its colour, folder and what goes on in it. Type to find one, or use the arrow keys and Enter (Enter alone goes back to the workspace before). What can be done with a workspace (new chat or task, add a folder, rename, new window, colour, remove) opens under its row; *Open a folder…* and *New workspace without folders* are at the foot. The column of icons has one *Workspaces* entry in place of a badge per workspace, so it no longer fills up, and the way to add one is always in view. A long folder path is cut to its end, and says all of it in a tooltip. The name itself is easier to see: full strength, with the workspace's letter on its colour and an outline.
- **Two keys between workspaces: ⌘E for the list, Ctrl+Tab for the one before.** ⌘E (Ctrl+E) opens the list on the workspace used before, so ⌘E then Enter goes back and forth as Ctrl+Tab does; the arrow keys or a few letters reach any other. Ctrl+Tab now also works right after a start. ⌃1–⌃9 (Alt+1–9) are gone: they counted the badges in the column of icons, and number nothing one can see in a list by last use.
- **The column of icons marks the place in front on its icon**: a rounded box behind the icon alone, with the name under it in full strength, where the box used to hold both and a long name touched its edges.
- **The live tools moved into the pane's toolbar.** Pick, mark, capture and record no longer float over the phone's screen or the page, where they always hid a part of it. The four kinds of mark are one button with a menu; Esc ends picking or marking. *Before/after* is gone. On the phone's toolbar, *Install an APK*, *Launch an app* and *Stream quality* are under **⋯**.
- **Nothing is cut off in a narrow pane.** At its narrowest the result pane keeps everything in reach: Preview's *Browser | Phone* switch becomes two icons (a globe and the Android mark), the phone's and the browser's live tools go into their **⋯** menu (the row keeps only what is going on: a mode to leave, the eraser, a recording to stop), and a long device name ends in an ellipsis.
- **Fixed: the outline of a picked element on a phone could not be taken off.** The eraser shows for it now, and it also goes with the next press on the screen.
- **Chat tabs: close others, close all.** A right click on a chat's tab has *Close tab*, *Close other tabs* and *Close all tabs*, over what can be done with the chat.
- **Utilities: in the column of icons, and each shown as what it is.** *Utilities* stands above Settings and opens the dialog over what is in front. Each utility now has a view made for it rather than one input over one box of text: JSON, YAML, TOML and XML in coloured editors side by side, an invalid text shown at its line with a mark under the place; a CSV as a table to sort; SQLite with its tables down the side and the rows in a grid; Base64, URL, hex and HTML editable on both sides at once (no Encode or Decode to choose), bytes shown as a dump and a picture as itself; a JWT coloured by part with its claims, dates and expiry, and its signature checked; certificates as cards with days left and the chain checked; a QR code as a picture to copy or save; every hash at once, of a text or a file, with a checksum compared; times in every form and the zones you add; a cron line in words with its next runs in local time or UTC; regex matches marked in the text, with replace; diffs as the Git tab shows them; colors with contrast and shades. Values are copied by a click. A view keeps what was typed while the dialog is open, and when one utility cannot read a text another can, it offers to open it there. The dialog keeps one size, opens on the utility used last, and finds one by typing.
- **New utilities:** passwords and keys, number bases, IP networks (CIDR), and text tools (cases, counts, and characters that cannot be seen or are not what they look like). UUID v7, SHA-1, SHA-384, SRI hashes, HMAC with SHA-1 and SHA-512, JSON to YAML and CSV, YAML and TOML to each other, colors in OKLCH, Android, Flutter and SwiftUI forms, CSS color names, and regex look-around and back-references.
- **Fixed: Enter in the Utilities search closed the dialog.** It takes the first utility found, as it said it would.
- **Workspaces, when there are none yet**, says what a workspace is and offers *Open a folder…* and *New workspace without folders*, where it used to ask for a folder at once.
- **Logcat: sideways scrolling, and an app picker to search.** With wrapping off, each line is one row and the list scrolls sideways. The app picker is a list to search, since a phone has more apps than a menu shows.
- **Logcat is opened from the phone's pane**: it is no longer in the result pane's ⋯ list of tools. Its drawer under the phone's screen gives it the whole pane.
- **The browser's start screen names both browsers**: the built-in one, and your own Chrome with its sign-ins, with a button to its settings.
- **Agents read one app's log**: `device_logcat` takes `package` (also for an app that crashed) and `level`.
- **Tests: the project's own tests are in the tab.** The Tests tab finds the project's suites (`cargo test`, pytest, Vitest, Jest, Playwright, Gradle, Maven, `go test`; in the project folder and the folders right under it), runs them with **Run all** or one at a time, and shows one line per test: passed, failed or skipped, why it failed, and the file and line, which a click opens. **Run failed** and **Run again** run only a part; **Fix with agent** hands the failures to a chat. Any other command can be added and passes or fails as it exits. **Stop** ends a run and what it started.
- **UI tests do the same thing every run.** A run starts clean: what the test's site keeps (sign-ins, storage) is erased first, and an app is started from its first screen. Before, a test that signed in passed once and failed the next time, and *Run on every size* failed by itself after the first size. Steps wait for their element (up to 10 seconds) in place of one retry, and checks read all the page says, not its first 4,000 characters.
- **UI tests name elements as a person would.** A step keeps what it clicked by what it is and says (the “Add” button by “Coffee”), not by its place in the page, so a row added above no longer sends the click to another row; two elements of the same name with nothing to tell them apart fail and say so. On a phone a tap is kept as the element under it and found again by its words or id, so a test runs on a phone of another size. Steps read in plain words ("Click the “Sign in” button").
- **UI tests: how a screen looks is checked where you ask.** A look check compares the screen with the picture accepted for it and counts any change, down to a few pixels (the old comparison of every step allowed 1% of the screen, which missed a misspelt heading and flagged nothing). *Ignore what changed* leaves a clock out from then on; a phone's status bar is left out always. The picture shows *Now*, *Accepted* and *Changes*.
- **UI tests: a password is kept on this computer.** A password typed while recording goes to the Keychain (Credential Manager on Windows), not into the test's file or a shell variable; where it is missing the run says so and asks for it.
- **UI tests: the tab stays, and says what to do.** A run no longer switches to the browser (**Watch** shows it); steps fill in as they end, with the screen after each, beside the steps or under the one picked in a narrow pane. An app that is not running is said before anything is tried, with a way to the Run tab. A new test asks one question, *What should it check?*, and starts at the page or app already open.
- **UI tests can be exported** as a Playwright test or a Maestro flow, for a build server.
- **UI tests and run configurations can be asked for in a chat.** Tell an agent, in a chat or a CLI session, what a UI test should check, and it makes the test, records it and runs it (`test_record`, `test_save`); tell it to add a run configuration, and it shows in the Run tab for you to start (`run_add`, with `run_list` and `run_remove`). An agent adds a configuration and never starts one, and adding asks for your permission.
- **Git: the row of test chips is gone.** Over the list of changes stood a chip for every test command the chat in front had ever run (dozens after a long chat, also with nothing changed). The Git tab now says what Git has to say; how a chat checked its work stays on its card on the Bridge.
- **Fixed: no apps listed on a phone with a second user** (Samsung's Secure Folder): the app pickers in Devices and Logcat were empty there.
- **Reviews: a review is finished in one step, and sent once.** **Finish review** on a pull request decides in one place what goes to GitHub: the agent's findings you tick (the others stay on this computer), your own comments, a note, and how it ends (comment, approve or request changes). It is one GitHub review, so the author is told once; before, the findings, a summary and an approval were three separate posts, every open finding went out as the agent wrote it, and the approval was a button at the bottom of another tab. A finding's wording can be edited before it is sent. Nits are not ticked unless you tick them.
- **Reviews: findings are written to be read.** A finding now says, for someone who has not read the code: what goes wrong (its title, a plain sentence), what happens, why it matters, and an example with real values, then the change that fixes it as a diff. The agent is also told to try to prove each finding wrong before it answers. The Findings tab shows each finding in full, with the two things a reviewer does most in sight (*Not a problem*, *Fix in a task*) and the rest under one menu, where it had nine buttons over the first finding and titles cut short.
- **Reviews: comment on a line.** In *Files*, a click on a line starts a comment on it (Shift-click for several lines), a suggestion the author can take with one click, or a question to an agent about those lines. Comments wait until the review is finished. What is said about a line sits under it: threads from GitHub, the agent's findings, your comments. Files are ticked off as read, and *Since your review* shows only what the author changed after it.
- **Reviews: lists by whose turn it is.** *Needs my review*, *Waiting for author* (pull requests you reviewed: they used to vanish from sight once reviewed) and *My pull requests*, each grouped by what needs doing: for your own, changes requested, checks failing, conflicts, ready to merge. Drafts and bots' pull requests are left out of what waits for you unless you show them. The lists are read while the app runs, so the count is current, and a new request for review is announced; an agent can review each new request by itself (Settings → GitHub, off unless turned on). Reviews of several at once run three at a time, with the agent and template chosen in the bar.
- **Issues.** A repository's issues are listed beside its pull requests, in Reviews and in a workspace's Pull requests tool. An issue's page offers **Fix in a task** (a task whose agent is given the issue and its comments) and **Copy for an agent**; a new issue can be written, with who it is assigned to. An issue opened from a review finding can be assigned too.
- **A failing check says why, and can be fixed.** The checks and the merge are now under a pull request's conversation. A failed check opens to what it pointed at and the part of its log around the first error, with **Fix in a task** and **Run again**. The merge says what stands in the way (a conflict, a missing review or check, a branch behind its base, with **Update branch**) instead of offering a button GitHub refuses.
- **Reviews know more of the repository.** A review is also given `REVIEW.md`, GitHub's path instructions (`.github/instructions/*.instructions.md`) for the files changed, and the issue a pull request says it closes. Checkouts of merged and closed pull requests are removed. A pull request is watched from the moment its review is sent.
- **Fixed: approving a pull request took one click and no confirmation**, was offered on your own pull requests (GitHub refuses that), and *Request changes* with an empty box failed at GitHub. Both are now in *Finish review*.
- **Fixed: tabs folded to icons though their names fitted** (a pull request's, and the Git tab's): the room they need was overestimated.
- **Reviews: the diff side by side, and a right click on its lines.** *Files* draws a change in one column or with the old and the new side by side. Lines are picked by dragging over them; a right click on a line or on the lines picked has the chat's agent explain them, and a file's menu has it explain the whole file's changes. The pull request's chat folds away from the title bar (⌥⌘B), as the list on the left does. A pull request's tabs now start with *Conversation*.
- **Chats has no colour.** The frame is plain when *Chats* is in front, as it is for the Bridge and Reviews, and its menu no longer offers one: colours tell your workspaces apart.
- **The architecture map is gone**, for now: it will come back as something better.

### Merge notes

- `presentations` now means Slides (`crates/slides`, `ph-slides`): decks are artifacts of the kind `slides`, so the key needs `artifacts` and does nothing without it. New crates: `ph-slides` and `ph-webview` (`crates/webview`: the system's web view inside a window). New dependencies: `wry` (MIT or Apache-2.0; macOS and Windows only, so Linux builds are unchanged), `objc2-web-kit`, `objc2-pdf-kit`, `objc2-app-kit`, `objc2-foundation`, `objc2-core-foundation`, `block2` (MIT; macOS), `webview2-com` and `windows` 0.62 (MIT or Apache-2.0; Windows); `ph-slides` uses `roxmltree`, `zip`, `image` (PNG), `base64` and `notify`, all in the tree before. `Cargo.lock` also names what `wry` would use on Linux and Android (GTK, WebKitGTK, `dom_query` and theirs); none of it is built, since `wry` is a dependency on macOS and Windows only.
- The old presentation editor is removed: `crates/studio/src/slides/`, `crates/workspace/src/presentations.rs`, `crates/mcp/src/tools/slides.rs`, the `slides.*` control methods and the agents' `slides_*` tools (`slides_get`, `slides_edit`, `slides_undo`, `slides_themes`, `slides_export`). The agents' tools for a deck are `deck_guide`, `deck_look`, `deck_comments`, `deck_import` and `deck_export`. `ph-studio` no longer depends on `cosmic-text`, `fontdb`, `svgtypes`, `roxmltree`, `pdf-writer`, `svg2pdf`, `zip`, `syntect` or `dirs`. `PILOTHOUSE_PRESENTATIONS` is no longer read. `ph_workspace::open_in_studio` opens pictures and videos only.
- The actions `ph_workspace::NewPresentation` and `OpenPresentation` are gone; `ph_workspace::NewSlides` makes a deck. In Files, the entry for a `.pptx` is *Open as Slides* (button id `open-as-slides`, before `edit-slides`); it shows only with `presentations` and `artifacts` on (`ph-files` now depends on `ph-brand`).
- Agents have two more deck tools, `deck_create` and `deck_list`, and the others take `deck` (which of a workspace's decks). A deck made from a workspace's chat has that workspace as its `source` in `artifact.json`. New: `ph_agent::own_files` (folders outside a workspace that its chats change without asking, set by `ph_workspace::artifacts`), `ph_artifacts::Artifacts::set_source`, `ph_artifacts::workspace_of`, `ph_artifacts::start`, `ph_slides::Decks::{create_for, of_workspace, drawer}`. New settings key: `slides.chat.<deck>`. New element id: `deck-workspace`. A deck's page takes `?preview` (the slides alone, with *Open in Slides*).
- Names that stay, new: a deck's files (`deck.json`, `deck.css`, `slides/*.html`), the `data-id`, `data-chart` and `data-shape` attributes on slides, and the `/_artifact/slides/` paths the deck's page calls. `artifact.json` has a new field, `kind` (left out for a plain page).
- `ph_artifacts::Host` has two new fields, `renamed` and `kinds` (`ph_artifacts::NewKind`: a kind of artifact the list makes and opens in a window of its own, with the picture of its card, `art`); `ph_artifacts::library::create` takes the kind; `ph_artifacts::Kind` and `Server::add_kind` let a crate serve an artifact kind's own page and calls. `ph_agent::ChatContext` has a new field, `own_files` (a folder the chat's agent changes without being asked); `Store::move_presentation_space` is new.
- New `[features]` key: `tour` (on unless switched off): the welcome tour (`crates/workspace/src/tour/`), opened by `ph_workspace::tour::open_if_due` from the app's start; the action `ph_workspace::ShowTour`. Its cards name PilotHouse's own features and leave out those a build switched off; a build with features of its own adds cards to `CARDS` (with ids of its own) or switches the tour off. New settings key: `tour.seen`. New environment variable: `PILOTHOUSE_NO_TOUR`. New element ids: `tour-next`, `tour-back`, `tour-done`.
- The status bar's element ids `status-limits` are gone; the item is `status-usage` (its pop-up's button `status-usage-all`). The column of icons keeps its ids (`view-workspaces`, `view-chats`, `view-bridge`, `view-github`, `view-artifacts`) in a new order; an organisation's own views still follow *Artifacts*.
- The menu bar has an *Edit* menu (`crates/app/src/menus.rs`), with the system's Cut, Copy, Paste and Select All: a web view in a window gets those keys only from it. New element ids: `artifact-new-slides`, `deck-chat`, `deck-chat-edge`, `deck-open-browser`. `ph_theme::fonts::WEB_FACES` lists the bundled fonts for a web page.
- New `[features]` key: `artifacts` (on unless switched off): the *Artifacts* place, the palette's *Show Artifacts* and the agents' `artifact_` tools (`artifact_guide`, `artifact_publish`, `artifact_list`, `artifact_data`). New crate `ph-artifacts` (`crates/artifacts`), wired in `ph_workspace::artifacts`; `View::Artifacts` and the action `ShowArtifacts` are new (a `match` on `View` needs the arm). `ph_browser::Browser::capture_png` is new.
- Artifacts are kept in `Documents/<name> Artifacts` (the brand's name); `PILOTHOUSE_ARTIFACTS` names another folder, and a run with `PILOTHOUSE_DATA_DIR` set keeps them in `<data dir>/artifacts`. Each is served on a loopback port of its own between 23100 and 23999. Names that stay: `artifact.json`, `window.artifact` and the `/_artifact/` paths (pages are written against them). New element ids: `view-artifacts`, `artifacts`, `artifacts-list`, `artifacts-folder`, `artifact-<id>`, `artifact-name-<id>`, `artifact-more-<id>`, `artifact-share`, `share-start`, `share-copy`, `share-link`, `share-take-part`, `share-new-link`, `share-stop`, `share-done`.
- A shared artifact listens on every interface, on a second port of the same range, only while its owner shares it; an organisation that does not want that switches `artifacts` off. New dependency: `if-addrs` (MIT OR BSD-3-Clause), for this computer's address on the network.

## 0.6.3

- **Copy rendered Markdown as rich text.** Text selected in a Markdown document (the formatted editor and the preview) or in a chat reply is copied as plain text and as HTML, so it pastes into Confluence, a mail or a document with its headings, tables, lists and code, as from VS Code's Markdown preview (macOS and Windows).

A turned screen is now seen in the video, and the phone is asked only then. A still screen also costs the computer less.
- **Files:** a strip under the tree stays free for the folder's menu and for drops, however many files there are; the tree is read again when you come back to the window (for folders whose changes the system does not report, such as network drives) and by a new **Refresh** button; it is drawn again only when a folder's listing changed.
- **A file opened in a window of its own** (from Explorer or Finder) has its **Edit** button for pictures and videos, and now PowerPoint decks: Studio opens without a workspace. The Markdown views and *Format* for JSON are there too.
- **Helper processes have names.** The MCP bridge of each agent session and the Antigravity bridge show as `pilothouse-mcp` and `pilothouse-agy-acp` in Task Manager and Activity Monitor, not as more copies of `pilothouse`.
- **Windows fixes:** *Show in Explorer* works for files and folders below the workspace's top folder (and copied paths use `\` throughout); Studio's title-bar buttons (**Export…**, undo, redo, ⋯) take clicks; a video export no longer ends with "access is denied" (the finished file is closed before it is moved, the move is tried again for a moment, and a file that is open elsewhere is left alone, the result saved beside it).
- **Browser:** a stopped browser says it is stopped, with **Start the browser**, instead of "Starting the browser…" with a spinner that never ended; the menu's Stop also stops a browser that is still starting. Agents are told that the built-in browser is driven with PilotHouse's own browser tools (an agent with another browser or REPL tool of its own tried that one, and failed).
- **Lighter while agents work.** The Git tool read the whole working tree (three `git` runs, one a full `git diff`) on every change to a file, shown or not, for every workspace with its Git tool opened once. It now does so only while it is on screen, at most every five seconds for the count on its icon, and not at all for a workspace that is not in front; reads no longer run back to back while files keep changing, and one that finds nothing new draws nothing. Git and the file in front are also read once when you come back to the window.
- **Lighter in the background.** With PilotHouse behind another program, the status bar's look at ports and CI runs once a minute instead of every ten seconds, and no longer starts `git` each time to see whether the commit changed. On Windows it started `netstat` twice and `tasklist` every ten seconds for ports it could never show there; it no longer does.
- **Fixed: the app's log lost to other runs.** Opening a file with PilotHouse from Explorer or Finder, the quick chat shortcut, `pilothouse --version` and `--help` each started a new log file, moving the running app's log along until what it had written was gone. Only the app itself starts its log now.
- **Fixed:** opening a tool from the icon bar while the Chat tab was in front no longer brings the Editor tab forward; the Agents pop-up scrolls when its list is longer than the window.

## 0.6.1

- **Builds for organisations.** Everything an organisation changes now lives in a few places of its own. [docs/customizing.md](docs/customizing.md) explains each:
  - `brand/` holds the name, ids, icons, features on or off, and update sources, read by the app and by the packaging scripts.
  - `crates/custom` holds the organisation's own views beside Workspaces and GitHub, its commands and its startup code.
  - `CUSTOM.md` holds the organisation's rules for coding agents.
- **Coding agents get context.** [AGENTS.md](AGENTS.md) (and `CLAUDE.md`) covers how the code is laid out and its rules, and a `merge-upstream` skill takes in a new PilotHouse release.
- An organisation's tables go on a migration track of their own (`Store::apply_track`), so they never take PilotHouse's numbers.
- Appearance preferences that a build does not know (a newer one's, or an organisation's) are kept when it saves.
- `scripts/package/icon.py` now makes every icon from one picture (it used to draw an old version of the icon).
- **A new Walkthrough for pull requests.** For the tech lead or manager who reviews a change: a briefing in plain words, written by an agent that read the change and the code around it. It covers what changes and why, how that part of the system works today, what is different after (with diagrams), how it is done, what it affects, where to look closely, how it is tested and what to ask the author. Its text can be selected and copied, and references to code open in the Files tab or on the web. It replaces the gist, file groups and tour, and the tour strip in the Files tab; a walkthrough made by an earlier version is asked for again.
- **Cline.** Cline's CLI joins Claude Code, Codex, Gemini CLI and Antigravity, with your own install and sign-in (`cline --acp`): chats with its models and its Plan and Act modes, PilotHouse's MCP tools and yours, one-off jobs like commit messages, its sessions in the usage dashboard, and Cline in a terminal with its past sessions to resume. It runs as in your terminal: on a provider Cline uses there that needs no key (Vertex AI, Ollama), not only on a Cline account. Where Cline's ACP side falls short, PilotHouse works around it: attachments go as text, tool titles that are JSON read as words, a reopened chat is recapped to a new session, it neither updates itself nor leaves a background hub running, and an expired sign-in says so with a way to sign in again.
- **Quick chat.** A small chat window over every app, from anywhere: ⌥Space on macOS, Alt+Shift+Space on Windows and Linux (set it in Settings → Chat), the command palette, or `pilothouse quick-chat` for a shortcut in the system's own settings (the only way on Wayland). It moves, resizes and comes back where it was, with the chat it showed; its chats are under Chats. [docs/features/quick-chat.md](docs/features/quick-chat.md)
- **Agents in a terminal stay in the chat list.** A coding agent's CLI run in a workspace terminal is saved as a chat once it is asked something. With its terminal open, clicking it shows the terminal; once closed, it shows the agent's last answer under its title, its session read only in the chat column, with *Continue in terminal* (the CLI resumes it) and *Continue in a new chat*, and Search chats finds what was said in it. Closing a terminal whose agent is at work or waiting for you asks first. Cline in a terminal is followed too, its transcript readable. Cline's provider can be chosen in the chat (⋯ → Provider): its accounts, and the providers saved with `cline auth` that need no key.
- **Clearer agent errors.** When an agent fails a request with a reason (Cline's "Internal error" carries one), the chat shows the reason. A sign-in that expires mid-chat offers the agent's sign-in, and a chat whose agent could not resume its session (a failed load) now gives the new session the chat's history. A remembered model the agent no longer offers is not asked for again.
- **Diagrams zoom.** Hovering a Mermaid diagram, in a chat, a pull request's walkthrough or a Markdown document, shows buttons to zoom out, zoom in, fit, open it large in a dialog and copy its source; a pinch or ⌘/Ctrl and the wheel zoom too.
- **Lighter while agents work.** An agent working in a terminal no longer redraws every window four times a second, nor writes to the database each second; the sidebar shares its chat lists instead of copying them on each draw, and the Chats list shows its 50 newest (*Show all* for the rest). A closed terminal's session file is not looked for again and again, a quick chat window saves where it is once it stops moving, and Cline's settings are read once per change, without waiting for the login shell.
- **Fixed: a database backup of one kind deleting the other.** Backups made before a migration and those made before an organisation's own migrations are now kept apart, three of each.
- **Fixed: Cline's provider changed in one workspace** now starts Cline again in every workspace, so none keeps running on the old one.
- **Fixed: agent processes left running.** A new chat that was replaced before its first message, or switched to another agent, left its agent session open until PilotHouse quit. The same happened to deleted chats and to chats let go of as idle. For Claude Code that is a process of its own with its MCP servers, hundreds of MB each. Sessions now close with their chat (`session/close`, where the agent offers it), and *New chat* on a still untouched chat keeps it.
