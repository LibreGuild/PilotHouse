# Terminal

Crate: `ph-terminal`.

- Each tab is a shell in the workspace's primary folder (its scratch folder when it has none), on a real PTY, with `TERM=xterm-256color` and truecolor. **+** lists the shells installed here, your default first (`ph_env::shells`): on macOS and Linux those in `/etc/shells` plus fish, nu and pwsh when on `PATH`, each as a login shell; on Windows PowerShell 7, Windows PowerShell, Command Prompt, Git Bash and WSL, as found. With several folders, each shell has a submenu of them. A folder on a network drive always gets the server's shell.
- **Split.** The split button (beside **+**) puts a new shell beside the one in front, both shown: any installed shell, in the folder of the one beside it (⌘\ on a Mac, Ctrl+Shift+5 elsewhere, as in VS Code, for your default shell). Up to four side by side; drag the dividers. Each keeps its own tab, marked as split, and picking any of them shows the split; pressing in a pane puts the keyboard there (a line above it says which). Closing a shell takes it out of its split; *Unsplit* in the split button's menu shows them one at a time again, still running. Only the shells on screen are drawn.
- Emulation (escape codes, grid, 10k lines of scrollback) is `alacritty_terminal`. PilotHouse draws the visible grid as styled text and maps keys to bytes (`keys.rs`).
- The 16 ANSI colors are a palette tuned for terminals (`palette.rs`), one for dark mode and one for light; background, text, cursor and selection follow the theme. `CLICOLOR=1` is set (unless you set it), so macOS `ls` and other BSD tools colour their output.
- Output bursts are coalesced into one redraw. Wheel scrolls the history, and typing jumps back to the live screen.
- **Select** by dragging; double-click selects a word, triple-click a line. The drag follows the pointer anywhere in the window and ends where the button is let go, even outside the terminal; held above or below the terminal, it scrolls the history and keeps selecting. ⌘C copies (Ctrl+Shift+C on Windows and Linux, where Ctrl+C stays the interrupt). Typing clears the selection.
- **Right-click** in a terminal: *Copy* (dimmed with nothing selected), *Paste*, *Select All* (the history too), *Find*, *Ask in Chat About the Selection* (or *the Screen*), *Split Terminal* (beside the pane right-clicked) and *Clear* (the history and the screen, keeping the line you are on at the top, as VS Code does; nothing is sent to the program, and a full-screen program such as `vim` keeps its screen). Clear has no key of its own: ⌘K is the command palette everywhere.
- **Shift+Enter is a new line, not "send",** in a program that takes several lines (an agent's CLI): it types a line feed, what Ctrl+J types, which Claude Code, Codex and Gemini CLI read as "new line". To a shell it is Enter, as before. Alt+Enter types Escape and Enter, their other way to say it (`keys.rs`).
- **A program that asks for the mouse gets the clicks** (vim, htop, a full-screen agent): press, release, and the cells a drag passes over when it asks for those. Hold Shift to select text instead, as in other terminals. The wheel goes to such a program too.
- **Paste takes more than text.** Files copied in a file manager paste as their paths, and an image on the clipboard (a screenshot) is saved to a file in the system's temporary folder and pasted as that file's path: a terminal takes only text, and an agent's CLI attaches an image it is given the path of. Files dropped on a terminal are typed as their paths the same way, quoted where they must be.
- **⌘-click** (Ctrl-click on Windows and Linux) on a link in the output opens it (`links.rs`): a web address on this computer (`localhost`, `127.0.0.1`) in the Browser tool, any other in the system browser; a file path, with its line when printed as `path:line:column` like compiler and test output, in the editor when it is in one of the workspace's folders.
- **⌘F** (Ctrl+Shift+F on Windows and Linux) finds text in the history and screen (`search.rs`): the bar at the top right selects each match and scrolls to it; Enter goes to the next older match, Shift+Enter to the newer one, Esc closes it. The text is matched as written, ignoring case.
- **⌘L** sends the selection (or, with none, what is on screen) to the chat as an attachment, for "why does this fail?"; the composer waits for your question.
- ⌘V pastes (bracketed paste when the program asks for it). ⌘ shortcuts otherwise go to the app.
- Tab names are short: a prompt title (`ada@host:~/code/app`) shows as the shell and folder (`zsh · app`), a running program's title stays as it is, cut to 24 characters, and a run configuration's terminal keeps its name.
- Shells start only when the Terminal tab is first opened, and they keep running while the app runs. Closing a tab ends its shell.
- **Kept between runs.** When PilotHouse quits, each workspace's terminals (up to 8, the last 2,000 lines of each) are written as plain text to `<data dir>/terminals/<workspace id>.json`. The next time the workspace's terminals are wanted (its Terminal tab, a run, an agent), each comes back as a new shell with that text above it, dimmed, under a "from the last run of PilotHouse" line. The file is read once and removed. Programs do not come back (a shell cannot be resumed); colors and escapes are left out.
- **Shells belong to the workspace, not the tab.** A `Terminal` (`terminal.rs`) is the shell and its screen; `TerminalView` only draws one; `WorkspaceTerminals`, held by the `TerminalHub` global, is a workspace's list. So a shell keeps running when the tab's panel is rebuilt (folders added, the workspace moved to another window, an idle screen closed), and a new view picks it up as it is.

## Agents in a terminal

The Terminal tab is for terminals. An agent's CLI is started from the chat, where it is a session's other form (**Chat | CLI** in the chat's header, [chat.md](chat.md#chat-or-cli-one-session-two-forms)); the **+** here offers shells only.

An agent's CLI you start by hand in a tab (you type `claude`, `codex`…) is followed all the same (`ph_workspace::terminal_agents`): the tab shows a spinner while it works, an amber dot when it waits for you (a permission, a question, a sign-in, a folder to trust), a green dot when it finished a turn you have not looked at (looking at the tab clears it); it gets a card on the Bridge (with what it runs, asks or replied last), and notifications and the Dock badge count it like a chat. How PilotHouse knows, best first:

- **Hooks** (Claude Code started by PilotHouse, as a session's CLI): `claude --settings <file>`, a settings file of PilotHouse's own (in the data folder's `terminal-agents/`, cleared at start) with hooks on `SessionStart`, `UserPromptSubmit`, `PreToolUse`, `PostToolUse`, `Notification`, `Stop` and `SessionEnd`. Nothing is written to `~/.claude`. Each hook runs `pilothouse agent-hook --socket <control socket> --pane <id>`, which passes the event (stdin) to the app as `agent.event` and always succeeds silently, so the agent is never held up. They give the prompt (the card's name), each tool, the last reply, and which of its sessions it is on.
- **Program status** (OSC 7501, `ph_terminal::program_status`): Codex, Antigravity and Claude Code write their own state into their output once the terminal says it understands. The PTY's output is read through a tap that passes every byte on to the emulator and picks these reports out, and answers the probe. This works for an agent started by hand in any tab.
- **The title** (Gemini CLI, which has neither): it puts ◇ ready, ✦ working or ✋ action required at the start of the terminal's title.
- **Started by PilotHouse** (Cline, which says nothing of its state): known while its terminal is open, though without a state of its own.

Programs that ask the terminal for its colours (OSC 10/11) get the ones they are drawn with.

**Chats that stay.** An agent in a terminal that was asked something is saved as a chat of the workspace (kind `terminal`, `terminal_agents::remember`): its title (the first thing asked, or its session's title from its file), its own session id (from its hooks, the one it resumed, or found in its files, `find_sessions`: 30 seconds after it starts, then twice as long after each look in vain up to 10 minutes, and soon again once it is asked something; never a session a chat of the workspace already has) and when it last did something. While its terminal is open the list shows it live, and clicking it shows the terminal. Once the terminal closes it stays in the list, and opens in the chat's place in its CLI form: its session file read only, **Continue** to go on in the CLI there, or the header's **Chat** to go on in the chat. The transcript beside a tab (the button on an agent's tab) shows the same file while the terminal is open.

**Closing a busy agent's tab** (its tab shows it at work or waiting for you, or the program says so) asks first: closing stops the agent.

**Transcript** (the speech-bubble button by **+**, on an agent's terminal) shows its session beside it, as a read-only chat: what was asked, what it said, and the tools it ran (`ph_agent::cli_transcript`). It reads the agent's own session file (from its last 4 MB), the one its hooks name for Claude Code, else the one it resumed or the newest in the folder since it started, then only what is added as it grows, off the UI thread. Claude Code, Codex and Gemini CLI keep one; Antigravity does not. The divider between the two drags.

Not on network drives (the hooks call this computer's PilotHouse). Codex, Gemini CLI and Antigravity ask once to trust a folder; that is their own question and answer.

Not yet: mouse reporting to programs (e.g. clicking in `htop`).
