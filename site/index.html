01 Steer

Every agent, every workspace, at a glance.

Run agents in many repositories at once. The Agents panel (⌘⇧A) says which one waits for an answer, which are working and which just finished, and a click takes you there. No more checking every terminal and tab.

  • Needs you rises to the top, amber, with the question it asks.
  • Working shows what the agent is doing right now.
  • Finished stays green until you have looked.
  • The inbox gathers approvals, your reminders and schedules that ran; the system tells you when a chat needs you.
  • While you were away: coming back to a workspace shows what finished, one click each.

  1. 02 · 1

    Workspaces that say what they are doing.

    Every folder or repository is a workspace with its own chats, colour and status: needs you, working, failing, done. One workspace can hold several folders. Fold one, pin a chat, open another in its own window.

  2. 02 · 2

    See the plan, the steps and the result.

    Agents speak the Agent Client Protocol: their plan ticks off as they go, every read, search, edit and command shows in place, and the turn ends with what changed, Review changes and Undo turn.

  3. 02 · 3

    Git beside the chat.

    Each changed file with its lines added and removed and what happened to it. Keep or discard a hunk, write the commit message with an agent, or have one review the changes before you push.

  4. 02 · 4

    Every change, side by side.

    One file or all of them open as a diff in the editor, unified or split, new files included, with syntax colours. Thousands of files scroll without a stutter.

  5. 02 · 5

    Plans that read like documents.

    Markdown opens formatted and edits in place, a block at a time: double-click a heading or a table cell and type. Mermaid diagrams draw as you write, and copying gives you the Markdown back.

  6. 02 · 6

    Nothing runs without you.

    Commands and edits ask first when you want them to. Here Codex waits to run ./scripts/deploy.sh staging: the question waits in the chat, in the sidebar and in the Agents panel until you answer, and the Mode button sets how much an agent may do on its own.

05 Show it

Point at the screen. Not at words.

The browser and the phone are live in PilotHouse, and so are the marks you draw on them. Put a box, an arrow or numbered pins on what is wrong, and ⌘⇧S sends the frame with them to the chat.

  • Pick an element: its selector, the CSS that shapes it, and its source file and line when a dev build tells.
  • Record a GIF, or before and after with a diff of what changed.
  • Your own Chrome for real websites, through PilotHouse's extension: agents work only in its PilotHouse tab group, with your sign-ins, a glow where they act and a Stop button. Share a tab by dropping it in the group; agents never type into password fields and leave CAPTCHAs to you.

06 Pull requests

Reviews with evidence, posted where they belong.

The GitHub view (⌘⇧G) lists what waits for your review across repositories. Ask an agent to review it, explain it or write a test plan: it works in PilotHouse's own copy, your checkouts untouched, and its chat only reads.

  • Findings with a severity, the evidence and a fix, posted on the code with one-click suggestions.
  • Walkthrough briefs the reviewer in plain words: what changes and why, how that part of the system works today, what is different after, with diagrams, and where to look closely; Watch tells you when the author pushes or answers.
  • Address comments on your own pull requests in a task, with a reply drafted for each.
  • Review before you push: the Git tab's Review puts its findings on your lines.
  • GitHub.com and GitHub Enterprise Server; tokens stay in the system's keychain.

07 Studio

Pictures, videos and slides,
made beside the code.

Mark up a screenshot for the bug report, trim the screen recording for the release notes, build the deck for Friday's review. By hand, or by telling the agent in the chat beside it, and every step can be undone.

Pictures

Point out what matters. Hide what should not be shared.

  • Arrows, boxes, numbered steps, highlights, spotlights and labels.
  • Blur or pixelate emails, tokens and faces.
  • Crop, a gradient frame with a shadow, PNG, JPEG, WebP or ICO. Edits are descriptions, so any step can change later.
Video

Cut the waiting out of a screen recording.

  • Split, cut, and speed parts up from 0.5× to 16× on a timeline of frames.
  • Labels, arrows and blurs that show for the seconds you pick; A and B measure the time between two frames.
  • MP4, HEVC, WebM or GIF; nothing is written until you export, always to a new file.
Slides

Decks you can open in PowerPoint.

  • Draft from a few lines, then say "make this bigger" about what you selected.
  • Charts, tables, icons, code and diagrams; transitions, builds and a presenter's view.
  • Open any .pptx, keep its template, export editable PPTX, PDF or pictures.

09 Automation

Work that carries on
while you look elsewhere.

  1. 08:30

    Morning summary

    A schedule asks the agent every weekday and keeps the chat under Runs. Every 15 minutes, hourly, daily or weekly.

  2. On a new PR

    Review a pull request

    PilotHouse looks every five minutes. The prompt says why now: which pull request opened.

  3. On files, commits

    When something happens

    Files change, a new commit lands, checks fail: each can start a schedule, never twice at once.

  4. 22:00

    Nightly UI tests, then a fix

    Chain schedules: when the nightly tests fail, ask the agent to fix them.

  5. Any time

    A task in a worktree

    New task makes a branch in its own worktree, runs the setup from pilothouse.toml and gives its dev server a port of its own. Your checkout stays as it is.

  6. Any time

    The board, card by card

    Work through board hands the agent the To do cards; a card linked to tests waits for them to pass.

  7. When only you can

    A to-do for you

    Agents leave you a to-do, with a reminder, for what only you can do: sign in somewhere, decide something.

12 Why native

One light window instead of five heavy ones.

PilotHouse is written in Rust and drawn by the GPU. No Electron, no bundled browser engine: one process holds every workspace, its agents, shells and test runs, and stays quick with all of them going.

13 Private by design

Everything stays on your machine.

  • No account, no backend, no telemetry. It talks to the agents you installed, to Git, and to the hosts you add.
  • Your agents, your sign-ins. It uses the CLIs you already have and never sees their credentials.
  • Careful with what it opens. Opening a project never runs its code; viewing a file never runs it either. Links in agents' replies open only when they are web or mail links.
  • Someone else's code stays theirs. Pull requests are reviewed in a copy, by chats that only read.
  • Tokens in the system's keychain, sent only to the GitHub hosts you added. The browser is driven over a private pipe, not a port.
  • Signed updates. Each update is checked against the release's signed checksums before it is installed.
  • Open source. Apache-2.0, built in the open, releases with build provenance.
