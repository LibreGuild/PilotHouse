Steering, not babysitting

Every agent, every workspace, at a glance.

Run agents in many repositories at once. The Agents panel says which one waits for an answer, which are working and which just finished, and a click takes you there. No more checking every terminal and tab.

  • Needs you rises to the top, amber, with the question it asks.
  • Working shows what the agent is doing right now.
  • Finished stays green until you have looked.

  1. 01

    Workspaces that say what they are doing.

    Every folder or repository is a workspace with its own chats, colour and status: needs you, working, failing, done. Fold one, pin a chat, open another in its own window.

  2. 02

    See the plan, the steps and the result.

    Agents speak the Agent Client Protocol: their plan ticks off as they go, every read, search, edit and command shows in place, and the turn ends with what changed and a way to undo it.

  3. 03

    Git beside the chat.

    Each changed file with its lines added and removed and what happened to it. Keep or discard a hunk, write the commit message with an agent, or have one review the changes before you push.

  4. 04

    Every change, side by side.

    One file or all of them open as a diff in the editor, unified or split, new files included, with syntax colours. Thousands of files scroll without a stutter.

  5. 05

    Plans that read like documents.

    Markdown opens formatted and edits in place: double-click a heading or a table cell and type. Mermaid diagrams draw as you write, and copying gives you the Markdown back.

  6. 06

    Nothing runs without you.

    Commands and edits ask first when you want them to. The question waits in the chat, in the sidebar and in the Agents panel until you answer.

New in 0.5 · Studio

Pictures, videos and slides,
made beside the code.

Mark up a screenshot for the bug report, trim the screen recording for the release notes, build the deck for Friday's review. By hand, or by telling the agent in the chat beside it, and every step can be undone.

  • Point out what matters with arrows, boxes, numbered steps, highlights and labels.
  • Hide what should not be shared: blur or pixelate emails, tokens and faces.
  • Ready for docs in one go: crop, a gradient frame with a shadow, and a size limit for the upload.
  • Cut and speed up the slow parts on a timeline of frames; nothing is lost until you export.
  • Labels, arrows and blurs that show for just the moments you pick, as it plays.
  • Fits where it is going: MP4, HEVC, WebM or GIF, under 50 MB for Confluence if you ask.
  • Draft a deck from a few lines, then say "make this bigger" about what you selected.
  • Charts, tables, diagrams and icons in a dozen themes, or your company's PowerPoint template.
  • PowerPoint in, PowerPoint out: open any .pptx, present with notes, export editable PPTX, PDF or pictures.

Why native

One light window instead of five heavy ones.

PilotHouse is written in Rust and drawn by the GPU. No Electron, no bundled browser engine: one process holds every workspace, its agents, shells and test runs, and stays quick with all of them going.

Private by design

Everything stays on your machine.

  • No account, no backend, no telemetry. It talks to the agents you installed, to Git, and to the hosts you add.
  • Your agents, your sign-ins. It uses the CLIs you already have.
  • Careful with what it opens. Opening a project never runs its code; viewing a file never runs it either.
  • Someone else's code stays theirs. Pull requests are reviewed in a copy where their settings, hooks and build scripts never run.
  • Open source. Apache-2.0, built in the open, releases with build provenance.
