One window for your coding agents.

PilotHouse is a desktop app for working with Claude Code, Codex, Gemini CLI, Antigravity and Cline. They work on your code. You see what each one is doing, review what it changed, and decide what ships.

Download PilotHouse See how it works

It runs on your computer. No account, no server, no telemetry.

Why it exists

A day with coding agents usually means a few agent programs in terminals, an editor, a Git client, a browser to check the result, maybe a phone emulator, and a note somewhere saying which agent was waiting for an answer.

PilotHouse puts those in one window. Every project keeps its agents, shells and test runs going while you look at another one, and tells you when something needs you.

  1. You stay at the helm

    An agent asks before it runs a command or changes a file, unless you told it that it need not. Nothing is committed, pushed or posted until you say so.

  2. See it, not just hear about it

    Every change is a diff you can read line by line. Next to it stands what the agent ran to check its work: the tests, the commands, the screenshots.

  3. Yours, on your machine

    There is no PilotHouse account and no PilotHouse server. It talks to the agents you installed, to Git, and to the hosts you add yourself.

How it works

A task, from asking to shipping

Four steps, all in the same window. You can do the first and come back for the third.

  1. 1

    Ask

    Type what you want done. Point at things with @ instead of describing them: a file, a function, the screenshot on screen, a failing test, a pull request.

  2. 2

    Let it work

    The agent shows its plan and each step as it takes it. When it wants to run something, it asks. You do not have to watch: go to another project, and the Bridge shows a count when one of your agents is waiting.

  3. 3

    Review

    What changed is in the Git pane beside the chat: the files in a list, their diff next to it. Tick a file once you have read it. Keep or undo a single group of lines. Leave a note on a line and send your notes back to the agent in one message.

  4. 4

    Ship

    Commit, push and open the pull request from the same pane. The task's card then carries its branch, its pull request and whether the checks passed, so you can tell from the Bridge when it is safe to merge.

Features

What is in the window

Each part below is something you would otherwise open another program for.

The Bridge

Every task, sorted by what it needs from you.

PilotHouse opens on four columns: Needs you, Working, Ready for review and Done. Every chat of every project is a card in one of them. A card says which branch it is on, how much it changed, and how it checked its work.

If an agent is waiting for a yes or no, you can answer on the card without opening the chat.

A workspace for each project

The chat on one side, the work on the other.

A workspace is a project: one folder, several, or none. Its screen has two panes. One is the chat. The other shows one thing at a time, under four names:

  • Git: what changed, to review and commit, with branches, history and stashes.
  • Preview: the page or the phone screen the work shows up on.
  • Terminal: your shells, side by side if you like.
  • Files: the folder tree and an editor with language servers.

Several chats in one workspace are tabs over the chat, each with a small mark for what it is doing.

Reviews

For when you review other people's pull requests.

The pull requests waiting for your review, across your repositories, in one queue. Ask an agent to review one, or several at once. Each gets a list of findings: the problem, the lines that show it, and a fix.

You read them and choose which become comments. Nothing is posted to GitHub until you press the button.

A browser and phones the agent can see

So it can check what it built, and so can you.

PilotHouse has a browser of its own, and shows Android emulators and phones you plug in. You and the agent look at the same screen, and either of you can click, type and scroll.

Draw an arrow or a box on what you see and send it to the chat. That is often quicker than describing a layout bug in words.

Your own Chrome, when a site needs you signed in

An extension, and a tab group that is the agent's.

Some pages only work when you are signed in: a dashboard, an admin screen, your staging site. With PilotHouse's extension, an agent works in your Chrome, in a tab group of its own. It never sees a tab outside that group.

The extension's button sends the page, a screenshot or one element to a chat, and records a bug report with its video, console errors and failed requests. In Settings you choose whether agents reach for your Chrome or the built-in browser first.

Work that goes on without you

Schedules, triggers, and several attempts at once.

Give an agent a prompt to run at a set time, or when something happens: files change, a commit lands, a pull request opens, a check fails. The result is a chat like any other, waiting on the Bridge.

A task can have a branch and a folder of its own, so two agents never trip over each other. You can also send one prompt to several agents at once and keep the answer you like best.

Also in the box

Smaller things, each of which saves a trip to another program.

  • Quick chat

    ⌥Space (Alt+Shift+Space on Windows and Linux) opens a small chat window over whatever you are doing. Ask, and go back to it.

  • Chats without a project

    Not every question belongs to a folder. Those chats live under Chats, always in the same place.

  • Undo an agent's turn

    Before each turn PilotHouse notes how the files stood. Restore files under your message puts them back.

  • Hand a chat to another agent

    Stuck with one agent? Continue the same chat with another. It gets what was said and done so far.

  • UI tests in plain words

    An agent records a test by doing it once. After that it replays without any AI, on several screen sizes, and compares the screens.

  • Open almost any file

    Markdown as a document you can edit, images, video, PDF, tables, notebooks, databases, and logs of several gigabytes.

  • Agents in a terminal too

    Prefer an agent's own terminal interface? Run it in a workspace terminal. PilotHouse still follows whether it is working or waiting.

  • Studio

    Mark up a screenshot and blur what should not be shared, cut the waiting out of a screen recording, and make slide decks that open in PowerPoint.

  • Search every chat

    Find the conversation where that odd bug was explained three weeks ago, in any project.

  • Usage

    How much each agent has used, per day and per project, and how close you are to its limits.

  • Code on a network drive

    If your code sits on a server's share, Git and terminals run on that server over SSH, next to the files.

  • Themes

    Eight themes and an accent colour. Or describe the look you want and let an agent build the theme while you watch.

  • A to-do for you

    An agent cannot sign in for you or plug in a phone. It leaves you a to-do with a reminder instead, in the inbox.

  • Small utilities

    JSON, JWT, hashes, times, cron, regex, SQLite. They work offline, for you and for agents.

  • Your organisation's own build

    Set a name, icons and which features are on, add views of your own, and keep merging new releases.

Privacy

Everything stays on your computer

PilotHouse is a program on your machine and nothing else. It has no account to create, no server of ours to talk to, and it sends no usage data anywhere.

  • Your chats, settings and history are files in a folder on your disk. Settings shows where.
  • Each agent talks to its own service, with the sign-in you gave that agent. PilotHouse does not sit in between.
  • GitHub is reached only if you add an account, and only with the token you paste.
  • The Chrome extension asks for no site at all. It reads a tab only when you point at it.
  • The source is public, under the Apache 2.0 licence. You can read what it does, or build it yourself.

What it is not

PilotHouse is not an agent and has no model of its own. It works with the agent programs you install and sign in to yourself: Claude Code, Codex, Gemini CLI, Antigravity or Cline. Their makers set what those cost.

It is also young. It does not show iPhone simulators yet, only Android. The downloads are not code-signed yet, so macOS and Windows ask you to confirm the first time you open it.

It is one native program written in Rust, not a web page in a wrapper, so it starts fast and stays light with several projects open.
